# 로컬 Ollama 번역·요약 테스트

본 채널 운영과 분리된 테스트 경로다. 기존 Azure 번역·규칙 기반 발송을 대체하거나 운영 프로세스를 재시작하지 않는다.

확인 모델: `qwen3.5:9b` (9B, Q4_K_M). 이 프로젝트의 `.env`는 GPU 서버 `http://127.0.0.1:11435`를 사용한다. 로컬 주소만 허용한다. Python requests로 호출하며 Ollama Python 패키지를 별도 설치할 필요가 없다.

GPU 서버 시작/재시작(PC 재부팅 후에도 필요):

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/start_ollama_gpu.ps1
```

실행 정책 옵션은 해당 프로세스에만 적용되며 PC 정책을 변경하지 않는다. 내장 GPU와 Vulkan을 활성화한 별도 서버를 백그라운드에서 실행한다. 사용자 기본 Ollama 앱의 11434 포트와 본 채널 발송 프로세스는 변경하지 않는다. NPU는 이 경로에서 사용하지 않는다.

## 처리 경로

운영 DB 읽기 전용 조회 → 수집 당시 제목·기사 발췌/지표 원문 → 로컬 모델 한국어 제목·핵심 요약·상세 항목 생성 → JSON 구조 검사 → 각 항목의 원문 인용·숫자 검사 → 파일 저장 → 사람이 검토한 결과만 테스트 채널 발송.

`think=false`, `temperature=0`, JSON schema, 8,192 context와 최대 1,800 출력 토큰을 사용한다. 숫자·금액·비율은 보호 토큰으로 전달하고 결과에서 원래 표기를 복원한다. 근거 문장과 숫자 검사는 환각을 완전히 판정하는 장치가 아니다. 주체·인과관계·현재/전망·기간 관계에 대한 내용 검토가 추가로 필요하다. 숫자 단위 환산이나 비율 계산은 모델에 맡기지 않는다. 영문 분기·월 이름과 한국어 숫자 표기는 정규화해 검사한다.

기본은 파일 생성만 수행한다. 발송은 기존 파일을 재검증한 뒤 실행하며, 본 채널과 테스트 채널 ID가 같으면 중단한다. 운영 DB의 알림·중복 이력은 변경하지 않는다. 성공 발송 기록은 `data/ollama-preview/receipts.jsonl`에 남긴다. Telegram 응답이 불명확한 경우 자동 재시도하지 않는다.

```powershell
# 실제 수집·보존된 데이터 3건을 로컬 LLM으로 처리 (발송 없음)
.\.venv\Scripts\python.exe scripts/test_ollama_news.py --event-ids 94 58 87
# data/ollama-preview/event-*.html과 JSON의 근거를 확인한 뒤 테스트방 발송
.\.venv\Scripts\python.exe scripts/test_ollama_news.py --event-ids 94 58 87 --send-existing
```

환경 변수 `OLLAMA_MODEL`, `OLLAMA_BASE_URL`로 로컬 설정을 변경할 수 있다. `AI_SUMMARY_ENABLED`는 기존 코드의 별도 설정이므로 이 테스트를 위해 true로 바꾸지 않는다. 상시 자동 발송 경로에는 아직 연결하지 않았다.

입력은 새로 발표된 것처럼 생성한 기사가 아닌 실제 DB에 남은 메타 기사(94), Census 주택착공(58), 브로드컴 기사(87)를 사용한다. 원문 전체를 새로 수집하는 테스트는 아니며, 기존 발췌가 부실하면 LLM이 누락된 사실을 복원할 수 없다.

테슬라 공시 발췌(92)도 시험했으나 근거 밖 숫자와 기간 관계 오류가 발견되어 발송하지 않았다. 모델이 북미 인도량의 sequential(직전 분기 대비) 표현을 전년 동기로 잘못 번역했고, 인용 근거에 없는 TTM 매출을 해당 항목에 포함했다. 숫자 검사는 일부 오류만 잡을 수 있으며 전체 의미 검증을 대체하지 못한다. `failed-92.json`에 결과를 보존했다. 이 입력은 실적표의 표·각주·문장 복원이 선행되어야 한다.

Ollama API 참고: [공식 API 문서](https://github.com/ollama/ollama/blob/main/docs/api.md), [공식 구조화 출력 문서](https://ollama.com/blog/structured-outputs).

## 2026-10-22 실행 결과

실제 수집·보존한 입력을 로컬 모델이 번역하고 핵심 요약을 생성했다. 사람이 요약 문장을 대신 작성한 샘플이 아니다. 표시 제목은 회사명·자료 유형으로 정리하고, 통계 용어와 띄어쓰기는 코드에서 교정한다.

| 입력 | 처리 시간 | 테스트방 메시지 |
|---|---:|---:|
| Census 주택착공(58) | 56.08초 | 126 |
| 브로드컴 기사(87) | 108.75초 | 127 |
| 메타 실적 기사(94) | 70.72초 | 128 |

초기 생성의 금액 환산, 기간 혼동, 실적보다 AI 소개를 우선한 요약은 확인 후 제외했다. 금액·비율 보호 토큰, 실적 우선 지시, 회사명 중심 제목을 보완했다. 최종 메타 요약은 매출 성장과 비용 증가를 우선하고, 전망 및 순이익/EPS를 상세 항목에 배치한다. 일부 dollar/billion 표기는 원문대로 유지한다.

Ollama `/api/ps`에서 `size_vram=0`을 확인했다. 현 환경은 CPU 추론이며 3건 평균 벽시계 시간은 약 78.5초다. 처리 시간에는 입력 처리와 일부 대기 시간이 포함된다. 테스트 순간의 측정값이며 향후 지연을 보장하지 않는다. 상시 적용 시 단일 작업 대기열·캐시·지연/실패 처리 설계가 필요하다.

Ruff 검사 통과. 전체 테스트 267개 통과 후 최종 보호 토큰 변경에 대해 Ollama 관련 테스트 8개를 다시 통과했다. 본 채널 운영 프로세스와 운영 DB 전송 이력은 변경하지 않았다.
