# Ollama 운영 전환 (2026-10-23)

운영 경로는 중요도 필터 통과 → 기사/공시 본문 확보 → 로컬 Ollama 한국어 번역·요약 → 근거/숫자 검증 → 확정 양식 발송이다. Azure 키·리전·엔드포인트 설정과 Azure 호출 코드는 제거했다. `processors/translator.py`는 과거 스크립트 호환용 Ollama 별칭만 제공한다.

- `OLLAMA_BASE_URL=http://127.0.0.1:11435`
- `OLLAMA_MODEL=qwen3.5:9b`
- `OLLAMA_TIMEOUT_SECONDS=600`

프로젝트 GPU 서버는 `scripts/start_ollama_gpu.ps1`로 실행한다. Windows 운영 시작 시 위 주소의 서버가 내려가 있으면 같은 스크립트를 숨김 실행한다. 원격 Ollama 주소는 설정 검증에서 거부한다. 모델을 임의로 다운로드하거나 클라우드로 대체하지 않는다. 키가 필요하지 않으므로 Azure 리소스를 삭제해도 새 운영 경로에 영향이 없다.

모델 처리는 별도 단일 작업 스레드에서 진행한다. 수집 스케줄러와 SQLite 갱신/발송은 주 스레드에 남겨 긴 생성 중에도 다른 소스 수집을 계속한다. 생성 중인 알림은 `pending` 상태로 유지해 프로세스 중단 시 실제 발송 여부가 불명확한 알림으로 오인하지 않는다. Telegram 전송 직전에만 원자적으로 claim한다.

모델 입력에는 확보한 원문의 중요 내용 후보를 개수 제한 없이 넣으며, 긴 입력은 구간별로 처리한다. 근거 인용·숫자·기간·한국어 출력·개조체를 검증한다. 실패한 개별 항목은 해당 원문 근거만으로 재생성하고 재검증한다. 인용 끝 구두점이 빠진 경우에만 원문 그대로 복원할 수 있으며 근거가 다른 내용은 승인하지 않는다. 검증 실패·연결 실패 시 영어 또는 Azure로 대체하지 않고 보류·재시도한다. 재시도 및 알림 유효시간 제한은 기존 운영 정책을 따른다.

`source_metadata.ollama_summary`에 모델·입력 지문·정확한 근거 원문·검증된 결과·처리 시간을 보관한다. 동일 입력은 재사용하고 내용이 바뀌면 재생성한다. 사용자 메시지에는 모델명·처리 시간·검증 로그를 넣지 않는다. 출력은 국기, 굵게·밑줄 제목/카테고리, 개조체, 긴 항목 사이 빈 줄, 원문 및 채널 링크를 유지한다. 공시/기사/어닝콜/실적 일정 구분도 유지한다.

로컬 9B 모델은 즉시 결과를 반환하는 엔진이 아니다. 실제 GPU 검증에서 단문은 최초 모델 로딩 포함 약 95초, 긴 기사 첫 생성은 약 192초, 실패 항목만 재생성한 추가 처리는 약 50초였다. 기사 길이·GPU 부하·모델 상주 여부에 따라 달라진다. 단일 생성 작업을 사용하므로 알림이 몰리면 대기열이 생길 수 있다.

검증 자료는 `data/ollama-production/`에 보관한다. `verify_ollama_pipeline.py`는 운영 DB의 복사본과 테스트 채널만 사용해 실제 `Radar.dispatch`의 백그라운드 처리·캐시·발송을 확인하며, 본 채널의 과거 알림을 재발송하지 않는다. 기존 Azure 기반 발송 이력과 편집 알림은 변경하지 않는다.
